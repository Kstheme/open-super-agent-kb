# M4：本地 Web 应用与 pipx 安装

依据 [部署设计](../design.md#11-部署)、[M4 交付与验收](../design.md#m4-交付与验收) 和 [ADR-0002 单用户本地优先](../adr/0002-single-user-local-first.md)。复用 [M2 清单](./0003-m2-word-accessibility-checklist.md) 和 [M3 复核](./0004-m3-review-and-proposals.md)。

## Problem Statement

用户已经可以通过 CLI 导入资料、委托生成清单、核对证据和确认差异提案。第一次使用时，还要准备项目环境并记住多条命令。用户希望安装一个本地应用，直接在浏览器完成这些操作，尤其需要看清一条规则的原文位置、修改理由和历史版本。模型无法连接时，用户还需要继续查看已有资料，并知道怎样排查故障。

## Solution

交付可用 `pipx` 安装的 wheel。用户在干净 Windows 环境运行 `openkb init` 和 `openkb serve`，通过本机浏览器完成导入、生成清单、查看证据、提交新版资料、复核和查看历史。首条业务链路复用两份真实 Section 508 原件和一份独立标注的 Word 模拟修订。

浏览器提供资料、清单、复核三个工作区。用 `ui-ux-pro-max` 设计清晰的高对比界面，突出原文和差异。通过 `openkb doctor` 检查本地数据和模型连接的常见问题。

## User Stories

1. 作为首次使用者，我希望用 pipx 安装已构建的 wheel，以便在没有仓库和项目环境的电脑上使用。
2. 作为首次使用者，我希望初始化本地数据目录，以便知道账本和配置保存在何处。
3. 作为已有配置的用户，我希望复用模型配置，以便继续使用原来的端点。
4. 作为本地用户，我希望在浏览器打开应用，以便不用记忆每项业务命令。
5. 作为本地用户，我希望在界面看到当前模型和连接状态，以便确认应用是否可以发起需要模型的操作。
6. 作为本地用户，我希望模型密钥留在本机配置，以便浏览器页面不暴露密钥。
7. 作为遇到安装问题的用户，我希望诊断能分辨数据目录、SQLite、模型配置和端点问题，以便知道哪里需要修正。
8. 作为资料维护者，我希望从空账本导入本地资料，以便从自己的文件开始使用。
9. 作为资料维护者，我希望看到导入状态和资料版本，以便确认文件已成功纳入账本。
10. 作为委托用户，我希望生成四项 Word 无障碍自查清单，以便照着检查。
11. 作为清单使用者，我希望从条目查看原文摘录、版本和位置，以便核对检查规则。
12. 作为证据审阅者，我希望下载证据对应版本的原件，以便查阅完整上下文。
13. 作为资料维护者，我希望给同一份资料提交新版，以便复核原有清单。
14. 作为清单维护者，我希望并排查看旧规则和修改建议，以便快速看清适用范围的变化。
15. 作为清单维护者，我希望在提案旁看到新版证据，以便核实建议依据。
16. 作为清单维护者，我希望接受提案后看到新版本，以便使用已确认的规则。
17. 作为清单维护者，我希望拒绝提案并填写可选理由，以便记录为什么保留当前版本。
18. 作为证据审阅者，我希望分别打开清单 v1 和 v2 的证据，以便核对当时的原文和规则。
19. 作为键盘用户，我希望能聚焦并执行接受和拒绝，以便独立完成复核。
20. 作为窄屏用户，我希望旧规则、新建议和证据按顺序呈现，以便看清提案并作决定。
21. 作为模型暂时不可达的用户，我希望继续浏览已有资料、历史清单和证据，以便完成不依赖模型的工作。
22. 作为模型暂时不可达的用户，我希望需要模型的操作给出明确错误，以便修复连接后继续。

## Implementation Decisions

- wheel 包含启动入口和本地页面资源。干净 Windows 的验收通过 pipx 安装该 wheel，在源码目录外启动和使用。运行时不依赖 Node 或项目虚拟环境。
- 沿用单用户、单进程、单端口的本地应用设计，默认仅监听 `127.0.0.1`。首版采用服务端渲染 HTML，按需使用少量 JavaScript。
- `openkb init` 设置数据目录和模型配置，支持复用现有 `config.toml`。`openkb serve` 启动浏览器可访问的本地入口。界面呈现模型和连接状态，密钥仍由本机配置持有。
- 资料、清单和复核页面复用 M1–M3 已有业务实现和账本语义。界面直接呈现导入状态、待确认提案、确认结果和产物历史。浏览历史、证据和原件不依赖模型端点。
- 证据回点显示该证据所绑定资料版本的原文摘录和具体位置，并下载所绑定版本的原件。复核中的新版证据随提案展示。接受、拒绝和历史回查沿用 M3 的产物版本规则。
- 使用 `ui-ux-pro-max` 指导页面设计，采用浅色、高对比和深蓝主色。宽屏并排显示旧规则和提案，窄屏改为上下布局。接受和拒绝支持键盘操作，保留可见焦点以及文字状态。
- `openkb doctor` 检查数据目录写入、SQLite 打开、模型配置和端点连接。失败项显示具体原因。
- 演示包单独准备，包含两份 M2 真实原件和明确标为模拟修订的 Word 副本。用户通过同一套资料入口导入自己的文件。

## Testing Decisions

- **首选验收入口是安装后的浏览器。** 从干净 Windows 环境用 pipx 安装 wheel，在仓库目录外执行初始化及启动。通过本机地址加载全部页面和资源，核对实际安装的入口和浏览器可见行为。
- **完整业务链路。** 从空账本导入两份原件，核对导入状态和版本，交付恰好四项清单并逐项回点。提交模拟修订，核对只对「数据表格」出提案，展示旧规则、跨页新条件和新版证据。
- **确认与回溯。** 从相同基线分别完成接受和拒绝。接受后新版只更新「数据表格」，可打开 v1 和 v2 分别核对旧规则和跨页规则，下载对应版本的 DOCX。拒绝后当前版本保留，用户填写的理由可查。
- **诊断及只读可用性。** 正常配置下检查 doctor 的四项结果。模拟端点断开，核对具体失败原因、界面连接状态和需要模型的操作提示，同时验证历史清单、证据及已有资料可查看。
- **键盘和窄屏。** 用键盘完成提案确认操作，能看到焦点和结果，窄屏下依序查看旧规则、新建议和证据，并能操作确认。
- 新增验证聚焦浏览器输出、已安装命令的行为和诊断结果。沿用 M2 的证据回点用例与 M3 的提案、接受、拒绝和历史回查用例。M0 评测和 M1 的 100 份批量验收继续通过现有 CLI 验证。

## Out of Scope

- 公开发布到 PyPI。
- React 迁移、完整的浏览器 Word 阅读器。
- 浏览器内运行 M0 评测或 M1 的 100 份批量验收。
- 账号、多人协作和自动应用修订。
- FTS5、trigram 和 sqlite-vec 的完整诊断，随对应功能验收。

## Further Notes

- 原始资料和模拟修订用于演示真实导入、取证和复核。模拟规则不代表官方修订。
- 保存安装记录、四项清单、确认前后的版本与证据、诊断结果，便于复现验收。
