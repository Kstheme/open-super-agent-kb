# M3：资料变更复核与差异提案

依据 [系统设计 §8.3](../design.md#83-复核核心差异)、[M3 验收门槛](../design.md#m3-业务验收)、[ADR-0005](../adr/0005-block-identity-and-alignment.md) 和 [ADR-0006](../adr/0006-two-task-kinds.md)。沿用已验收的 [M2 清单](./0003-m2-word-accessibility-checklist.md) 和 [M0 评测规格](./0001-m0-eval-harness.md)。

## Problem Statement

M2 用户已经能拿到一份带原文证据的 Word 无障碍自查清单。当资料更新时，用户需要知道哪条检查规则真的变了、依据是什么，以及是否值得更新现有清单。只改措辞或移动原文位置也可能触发复核，逐条手动比对会花时间。用户还需要查回当时交付的清单和原文，以便解释历史检查结论。

## Solution

用户通过本地 CLI 提交同一资料的新版本。系统计算受影响声明，逐条判断规则的真值或适用范围是否改变。对有新版证据支持的实质影响生成差异提案，展示原条目、建议改法和新版证据。旧依据消失且找不到替代依据时，把该条列为「待人工核对」。

首条业务链路复用 M2 的四项 Word 无障碍自查清单和两份 Section 508 原件。用 Word 原件的独立模拟修订分别验收规则变化、措辞改写、位置移动和依据删除。接受提案后生成新版清单，拒绝则保留当前清单并记录决定。M3 的质量另用 M0 的 gold set 与 `regenerate` 比较。

## User Stories

1. 作为清单维护者，我希望复用 M2 已交付的清单，以便继续维护现有产物。
2. 作为资料维护者，我希望给同一份资料提交新版，以便复核有明确的新旧版本。
3. 作为清单维护者，我希望看到系统找到哪些受影响声明，以便知道复核覆盖了什么。
4. 作为清单维护者，我希望原文只挪位置时仍能正确对齐，以便避免无关提案。
5. 作为清单维护者，我希望查看措辞改写后「无实质影响」的判断记录，以便复核为何没有提案。
6. 作为清单维护者，我希望只收到规则真值或适用范围有实质影响的提案，以便集中处理必要变化。
7. 作为清单维护者，我希望提案说明原条目和建议改法，以便确认变化在哪里。
8. 作为证据审阅者，我希望每条提案能回到新版资料的具体位置，以便核对建议。
9. 作为证据审阅者，我希望对齐无法确定时看到明确提示，以便人工避免错用原文。
10. 作为清单维护者，我希望旧依据消失且找不到替代依据时看到「待人工核对」，以便知道哪条仍需确认。
11. 作为清单维护者，我希望提案待确认时仍可使用当前清单，以便由我决定是否采用变更。
12. 作为清单维护者，我希望接受一项提案后生成新版清单，以便读取已确认的规则。
13. 作为清单维护者，我希望接受提案只更新接受的条目，以便保留其余检查内容和证据。
14. 作为清单维护者，我希望拒绝提案后保留当前版本并可填写理由，以便说明为何未采纳。
15. 作为证据审阅者，我希望查回旧清单和旧版本的原文证据，以便核对历史结论。
16. 作为项目维护者，我希望用同一套 M0 gold set 和模型配置运行两种复核系统，以便公平比较。
17. 作为项目维护者，我希望同时看到召回率、误报率、时延、token 和估算费用，以便判断复核的质量和代价。
18. 作为项目维护者，我希望看到失败、暂停和不可比的费用，以便保留评测的真实限制。

## Implementation Decisions

- 本地 CLI 显式提交新版并触发复核。复用 M1 资料身份、版本保存、块稳定键与原文回点能力，以及 M2 已交付清单的声明和证据引用。复核按 ADR-0006 使用委托与复核任务的预算语义。
- 按 ADR-0005 对齐新旧块，使用变更块到证据、声明的反查计算受影响集合，并记录归一化规则版本。对齐不确定时显式呈现。模型判断真值和适用范围是否有实质影响，判断结果可回查。
- 差异提案以清单条目为单位，记录旧条目、建议改法及支持改法的新版证据。旧依据消失且新版无替代时记录「待人工核对」，列出原声明和失去的旧证据，当前清单保留。
- 接受提案生成新产物版本，沿用清单条目的稳定身份，只应用已接受的变化。保留旧产物快照及其声明、原文版本和证据。拒绝时记录决定并保留当前版本，用户填写的理由作为 `edit_mark` 写回账本。
- 复用 M0 的 `ReviewSystem` 端口、报告与比较口径。评测标签用于计分，M3 被测实现按资料和清单进行复核。

## Testing Decisions

- **业务验收入口**采用本地 CLI。沿用 M1 的版本、对齐与证据回点测试，以及 M2 的真实 Word 原件。断言可观察的受影响集合、判断记录、提案、版本及证据。
- **实质变化**把重复表头规则改为只适用于跨页数据表格。只为「数据表格」生成提案，写明新范围并能回到新版原文。其他三项无需修改。
- **无实质变化**分别验收同义改写和无关插入。同义改写时该条进入复核、有「无实质影响」记录且无提案。无关插入时证据仍能对应新版位置，四项均无提案。
- **依据删除**移除重复表头依据并确认新版无替代。系统仅对该条报告「待人工核对」，列出原声明和旧证据。复跑后仍可读取当前产物，且没有生成相反规则或正式修订。
- **确认分支**用独立账本验收接受和拒绝。接受后新清单的「数据表格」引用新版证据，旧版四项和旧证据均可查回。拒绝时核对版本保持、决定落盘以及已填写的理由。
- **基线评测**用同一版 M0 gold set、同一模型配置运行 M3 和 `regenerate`，沿用 M0 宏平均及失败和暂停计分规则。质量门槛为召回率不低于对手、误报率不高于对手。报告总墙钟、模型耗时、token 和估算费用，缺少费用时记录为不可比。业务样本与基线评测独立记录。
- 沿用 M0 的建议性收缩规则。对手的召回率至少达到 M3 召回率减 5 个百分点，且估算费用低于 M3 并至多为其 80%，则提示考虑将账本收缩为只提供定位。最终取舍由人决定。

## Out of Scope

- 文件自动监控和浏览器操作。
- 对实际用户文档进行无障碍合规认证，以及扩充 M2 首条业务链路的四项清单范围。
- pipx 安装与本地 Web 演示。

## Further Notes

- 模拟修订用于可控验收，保留原件并标注每份副本的预期改动。
- 保存业务验收的提案、确认结果、产物版本和回点记录。基线留存两份 M0 格式报告及其比较结果。
