# 块身份靠稳定键对齐，不靠序号或偏移

复核链路的前提是"这份文档的这一块，在新版本里还是这一块"。`ordinal` 和 `start_offset` 都不满足：中间插入一段，后面所有序号漂移；docx 自动编号重排、pdf 版式微移，偏移一起作废。

决定：`block` 携带跨版本稳定的 `block_key` 与 `norm_hash`，由**归一化标题路径 + 条款编号（有则用）+ 归一化文本哈希**得出；`ordinal` 降级为排序提示，`start_offset` / `end_offset` 只用于证据定位。

块级 diff 的算法是：两侧按 `block_key` 求交 → 命中的做文本 diff → 未命中的按标题路径与相邻位置归入新增/删除。

## Considered Options

- **按 `ordinal` 对齐**：插入一段即全量漂移，受影响集合爆炸成误报。这是最容易犯的错，因为它"看起来能跑"。
- **按 `start_offset` 对齐**：等价于按字符位置比，任何版式变化都断链。
- **纯内容哈希**：改一个错字就断链，而"改一个错字"恰恰是最常见的真实变更。所以稳定键必须来自结构（标题路径、条款编号），文本哈希只作辅助。
- **用 embedding 相似度做对齐**：不可复算、结果随模型版本漂移、成本高；复核要的是确定性，不是"差不多"。
- **只做整篇语义 diff**：退化成 M0 的对手，账本不再有增益。

## Consequences

- 证据仍指向"具体版本的某个块"（`evidence.block_id`），稳定键只用于版本间对齐。两者职责分开：证据要精确到版本，对齐要跨版本。
- `norm_hash` 与归一化规则**本身要版本化**并写进 eval 报告，否则前后两次对齐不可比。
- 表格按行切块；合并单元格单独记一条规则，否则表格一改就整块断链。
- 纯扫描件等无法计算稳定键的格式，降级为"整篇作为一块"——**降级也不回到序号**，代价是误报率高但不会静默错配。
- **M1 的第一道 gate**：同一份文档两次导入（其中一次含无关修订）的块键一致率必须达标，不达标不许进入 M1 后续。这个指标现在就要写进里程碑，而不是等误报爆了再补。
- M0 提交的合成语料必须带 `block_key`。M0 不实现对齐，但数据形状必须与 M1 一致，否则类型改造会推迟到最贵的时刻。
