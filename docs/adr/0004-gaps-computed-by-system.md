# 缺口由系统计算，Agent 只认领和关闭

"缺口清零是停止取证的唯一条件"只有在缺口本身不可被 Agent 伪造时才成立。决定：委托开始时，声明模板把目标解析成一份**产物骨架**（产物的槽位结构）；缺口是骨架中尚未被 `active` 声明覆盖的槽位，由 `core/gaps/` 从骨架与账本计算得出，可复算。Agent 只能认领缺口、关闭缺口；若认为骨架不足，只能提交"建议新增槽位"（`skeleton_proposal`），由人确认后进入下一次委托。

这与"受影响集合由系统算、实质影响由 Agent 判"是同一条原则的第二次应用：**凡是能数出来的东西，不由模型数。**

骨架以数据形式（JSON）传入 `core/`，`core/` 不 import `profiles/`，因此 `design.md` §5 的三条不变量不被破坏。

## Considered Options

- **Planner 自己列缺口**：Agent 永远能列出新缺口，停机条件退化为预算上限，绝大多数任务以 `paused` 结束，`done` 几乎不可达；"能数出来"变成自述。
- **用反思轮数或置信度阈值作停止条件**：同样是调参，且无法向用户解释"为什么停在这里"。
- **用预算作唯一停止条件**：等于承认任务永远做不完，只是先暂停；缺口清单失去含义。
- **系统算缺口但允许 Agent 追加**：等于前者失效，因为追加即绕过。

## Consequences

- `core/gaps/` 是确定性模块，零 LLM 依赖；`agent/` 不得产生缺口。
- 声明模板要同时定义"声明长什么样"和"产物骨架长什么样"。换域 = 换模板，不换内核，这条不变。
- `task` 增加 `skeleton_json`；Agent 的追加诉求落在 `skeleton_proposal`，走人确认。
- `done` 的含义变成"骨架每个槽位都有有效声明"，可被单测锁定。
- 预算超限仍然是 `paused`，但它是例外路径而不是常规结尾；**`paused` 占比是产品健康度指标**，不是实现细节。
- 开放型委托（没有稳定骨架的"帮我调研一下"）不在 v0.1 范围内；它需要先能给出可复算的停止条件才允许进来，否则等于把闸门重新打开。
